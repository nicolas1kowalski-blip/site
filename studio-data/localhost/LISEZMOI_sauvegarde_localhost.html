💾 Sauvegarde automatique — ouvrir Studio Data en http://localhost

Ouvrir l'application via un petit serveur local (au lieu d'un double-clic file://) débloque la sauvegarde automatique sur un dossier de ton choix (indépendante de ton profil Chrome) et lève au passage le plafond mémoire sur les gros fichiers. Aucune installation requise.

🎯 Pourquoi

En file://, le navigateur interdit à l'app d'écrire dans un dossier : la seule sauvegarde possible est le stockage interne de Chrome, lié à ton profil. En http://localhost, l'app peut écrire sa configuration dans un dossier que tu désignes (idéalement synchronisé — OneDrive/Drive — ou réseau) : ta sauvegarde te suit alors d'un poste à l'autre.

🚀 Mise en route (une fois)

1 Mets, dans le même dossier, ces trois fichiers :
  • StudioDataV5.html (l'application)
  • Lancer_StudioData_localhost.bat (le lanceur)
  • serve.ps1 (utilisé seulement si Python n'est pas installé)
Astuce : renomme ton fichier en StudioDataV5.html (le lanceur détecte aussi tout fichier StudioData*.html, mais un nom propre évite les surprises).
2 Double-clique Lancer_StudioData_localhost.bat. Une fenêtre « serveur local » s'ouvre et ton navigateur affiche l'app sur http://localhost:8765/StudioDataV5.html.
Windows peut afficher « Windows a protégé votre PC » (SmartScreen) au 1er lancement : Informations complémentaires → Exécuter quand même. Le fichier ne fait que lancer un serveur local, rien ne sort du poste.
3 Laisse la fenêtre « serveur local » ouverte tant que tu utilises l'app. Ferme-la pour arrêter le serveur.

🔄 Reprendre ta configuration existante (une fois)

La version localhost est une « adresse » différente du file:// : elle démarre donc vierge. Pour récupérer ton travail actuel :

  1. Dans ta version actuelle (file://) : bouton 💾 Sauvegarde & partage → Exporter un bundle de partage → enregistre le fichier.
  2. Dans la version localhost : 💾 Sauvegarde & partage → Importer un bundle reçu → choisis ce fichier. Puis recharge tes sources (CSV).

📁 Activer la sauvegarde automatique sur dossier

  1. 💾 Sauvegarde & partage → 📁 Choisir un dossier de sauvegarde.
  2. Choisis un dossier synchronisé (OneDrive/Google Drive) ou réseau, et autorise l'écriture.
  3. C'est tout : l'app y réécrit ta configuration automatiquement au fil du travail. Sur un autre poste, ouvre le même dossier synchronisé et importe le fichier StudioData_secours.json qui s'y trouve.
Bonus : en localhost, les très gros fichiers passent mieux (débordement disque activé) — fini le plafond mémoire du mode file://.

🛟 Variantes & dépannage

SituationSolution
Le port 8765 est déjà utiliséOuvre le .bat avec le Bloc-notes, change set "PORT=8765" en un autre nombre (ex. 8790), enregistre, relance.
Tu préfères une commande manuelle (Python installé)Dans le dossier : py -3 -m http.server 8765 (ou python -m http.server 8765), puis ouvre http://localhost:8765/StudioDataV5.html.
Mac / LinuxDans le dossier : python3 -m http.server 8765, puis http://localhost:8765/StudioDataV5.html.
« Choisir un dossier » reste griséUtilise Chrome ou Edge sur ordinateur (l'API d'écriture dossier n'existe pas partout). À défaut, l'export/import de bundle reste disponible et suffit.
Le navigateur affiche une page vide au 1er instantLe serveur met ~1–2 s à démarrer : rafraîchis (F5).
À savoir. Cette sauvegarde reste 100 % locale (rien n'est envoyé sur internet — hormis le téléchargement du moteur, comme aujourd'hui). Le dossier de sauvegarde contient ta configuration (modèle, tables conçues, domaines, gouvernance, lineage, paramétrages…) ; les données sources, elles, se rechargent depuis tes fichiers.
